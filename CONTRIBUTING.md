# Contributing

Security-sensitive changes must be reviewed and tested. Use a feature branch and a pull request. Add unit tests for the policy engine or triage logic. For Terraform changes, include a resource/permission impact statement, security implications and cost estimate. Production applies must happen separately from read-only GitHub CI.

Avoid committing tokens, customer data, production alert payloads, or incident evidence. Never turn sample scores into claims of measured benchmarking. Do not alter existing AWS accounts or operational services without approval.
